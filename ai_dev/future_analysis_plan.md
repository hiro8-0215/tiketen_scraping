# 今後の分析・検証計画 (Future Analysis Plan)

データ（日々のスクレイピング結果および手動メタデータ）が十分に蓄積された後に実施すべき、より高度なAIモデルの分析・検証手法のアイデアをまとめました。

## 1. 時系列トレンド追従テスト（推移グラフ分析）
チケットの価格は「時間」とともに大きく変動します。AIがこの時間経過による相場変動を正しく予測できているかを視覚的に検証します。

* **検証方法:**
  横軸に「公演日までの残り日数（または特定の日付）」、縦軸に「価格」を取った折れ線グラフを作成します。
  1本の線は「実際の取引価格（平均・中央値の推移）」、もう1本は「AIの予測価格の推移」を描画します。
* **確認したいポイント:**
  * 「当落発表直後」「座席発表日」「公演直前」などの価格が急激に動くタイミングで、AIの予測もそれに追従できているか。
  * 「直前の投げ売り（価格暴落）」をAIが事前に予測（またはリアルタイムに反映）できているか。

## 2. 手動データ（定価等）有無によるA/Bテスト
自動収集データのみで学習したモデルと、定価などの手動メタデータを加えたモデルの精度を比較し、手動入力の価値を定量化します。

* **検証方法:**
  * **Model A:** 自動収集データのみ (`USE_MANUAL_DATA = False`)
  * **Model B:** 手動データあり (`USE_MANUAL_DATA = True`)
  上記2つのモデルを同じ条件（同じテストデータ）で評価し、MAE（平均誤差）やRMSEの差分を比較します。
* **確認したいポイント:**
  * 定価情報を入れることで、特に「価格帯別（定価以下〜プレミア）」の予測精度がどれくらい向上したか。
  * 手動データを収集するコストに見合うだけの明確な精度の差（例: MAEが3,000円縮まった等）が出ているか。

## 3. イベント（公演）ごとの「平均相場」予測検証
個別のチケット価格のブレ（出品者の気まぐれによる極端な高値・安値）を平滑化し、イベント全体としてのマクロな相場感をAIが捉えられているかを検証します。

* **検証方法:**
  イベントIDごとに、実際の全売買データの平均価格と、AIが予測した全チケットの平均価格を散布図でプロットします。
* **確認したいポイント:**
  * 「千秋楽だから相場が高い」「地方公演だから相場が落ち着いている」といった公演ごとの特性をAIが正しく理解し、イベント単位での平均価格を当てられているか。

## 4. 「座席品質」の価格感度（プレミアム）分析
良席と悪席で、AIがどれくらい価格に差をつけているか（感度）を分析します。

* **検証方法:**
  AIの内部データ（Partial Dependence Plotなど）を用いて、「アリーナ・アリーナ最前列」といった特徴量が、予測価格を「プラス何円」押し上げているのかを可視化します。
* **確認したいポイント:**
  * 実際の市場の感覚（例: アリーナ席は定価の+2万円、天井席は定価割れ）と、AIが学習したルールが一致しているか。手動データの座席情報がどう効いているかの確認になります。

## 5. 「お買い得判定」の追跡・実証テスト (バーチャル投資テスト)
AIが抽出した「お買い得チケット（予測相場より出品価格が著しく安いチケット）」が、実際に市場でどう動いたかをシミュレーション検証します。

* **検証方法:**
  過去のある時点（例: 公演1ヶ月前）のデータでAIに「お買い得チケット」を抽出させます。その後、そのチケットが「何日後に」「いくらで」売れたかを時系列データから追跡します。
* **確認したいポイント:**
  * AIがお買い得と判断したチケットは、実際にすぐに売れているか（流動性が高いか）。
  * 逆に、売れ残った「偽のお買い得（訳ありチケットなど）」の共通点は何かを探り、特徴量エンジニアリング（例: 塗りつぶし有無、連番の分断など）のヒントにします。
